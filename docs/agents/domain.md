# Domain documentation

This repository currently uses one domain context.

- Create `CONTEXT.md` at the repository root only when the first canonical term
  is actually resolved.
- Keep `CONTEXT.md` as a glossary without implementation details.
- Create architectural decision records under `docs/adr/` only for decisions
  that are hard to reverse, surprising without context and based on a real
  trade-off.
- Until a Wayfinder grilling ticket is resolved by Kim, proposed terms remain
  inside that ticket and must not be promoted to the glossary.

The current discovery effort must distinguish these concepts:

- **source:** an ongoing, partial and temporal input;
- **perspective:** a lens that reveals a contrast without becoming truth;
- **tension:** an actionable discrepancy made visible by a perspective;
- **mission:** a bounded invitation to act in the real world;
- **evidence:** material returned from the action;
- **gate:** the human review point that grants meaning or authority;
- **receipt:** the durable proof of what was accepted and changed;
- **world mutation:** the localized spatial consequence of a verified receipt.

These definitions are working vocabulary, not yet a new public contract.
